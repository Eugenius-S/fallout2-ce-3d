# Fallout 2: нативный просмотрщик карты с экспериментальным DLSS5

Дата: 2026-10-12. Исполнитель: другой агент, в том числе GLM 5.3 Flash.
Статус: спецификация для реализации; приложение ещё не создано, новый нейропроход не проверен.

## 1. Результат и границы

Создать отдельный Windows x64 просмотрщик **одной статической карты `kladwtwn`** из принадлежащей пользователю Fallout 2. Перенести представление сцены из Apolotary/fallout2-first-person в DirectX 12; получить настоящие буферы глубины и движения из своего рендера; проверить экспериментальный нейропроход DLSS5 через RenoDX.

Это технический прототип изображения. Бой, квесты, скрипты, сохранения, инвентарь, синхронизация с Fallout2.exe и полноценная игра в этот объём не входят. Персонажи стоят на месте, используются исходные текстуры и фиксированный кадр позы. Двери закрыты. Камеры: изометрическая и свободная перспективная без коллизий. Не создавать новые модели, PBR-материалы, трассировку лучей или генерацию кадров.

**Первым делом проверить нейропроход на синтетической сцене. До его приёмки карту не переносить.** Успешный перенос карты без работающего DLSS5 не означает выполнение всей задачи.

## 4. Что именно считается DLSS5

Выбран **экспериментальный NGX + RenoDX путь**, а не обещание официальной интеграции DLSS5 SDK. Программа вызывает публичный D3D12 DLSS SR/DLAA API. RenoDX перехватывает этот вызов и выполняет neural feature 18. Не придумывать прямой API feature 18 и не подставлять числовой feature ID в публичный SDK.

Нативная сцена → Color/Depth/Motion → NGX DLAA carrier → RenoDX neural pass → вывод в swapchain. Всё в одном x64 процессе на одном D3D12 устройстве и очереди. Реальные направляющие буферы устраняют необходимость Optical Flow, но сами по себе не гарантируют качество модели.

Начать с четырёх **локальных файлов, закреплённых SHA-256 в манифесте**: `dxgi.dll`, `nvngx_dlss.dll`, `nvngx_dlssnr.dll`, `renodx-dlss5.addon64`. Не смешивать их с более новыми пакетами. Название версии аддона недостаточно: ориентироваться на hash.

Три отдельных каталога запуска с одинаковым EXE и сценой:

| Режим | Файлы и поведение |
|---|---|
| `native` | Без ReShade/RenoDX/NGX runtime; прямой вывод сцены, NGX не инициализировать |
| `carrier` | Полный закреплённый комплект, `NeuralUplift=0`; NGX DLAA активен |
| `neural` | Тот же комплект, `NeuralUplift=1`; NGX DLAA и RenoDX активны |

Стартовый `ReShade.ini` для carrier/neural одинаков, кроме `NeuralUplift`:

```ini
[GENERAL]
PresetPath=.\ReShadePreset.ini
EffectSearchPaths=.\effects
TextureSearchPaths=.\textures

[RenoDX.DLSS5]
EnableHooks=2
NeuralUplift=1
NREnableUpscaling=0
NRFollowInputRes=0
NRResolutionScale=1
NRPreUpscale=0
NRPasses=1
NRAutoMask=0
NRIntensity=1
```

Это проверяемая стартовая конфигурация закреплённого комплекта, не универсальная схема всех RenoDX. Сохранить ini до/после запуска и проверить реальные настройки аддона после его миграции. Остальные эффекты ReShade выключены. Нельзя засчитать carrier как neural. Переключение режимов в интерфейсе запускает новый процесс с нужным каталогом; горячая правка ini во время измерения запрещена.

Результат G1 требует одновременно: библиотека загружена из ожидаемого пути; свежий журнал RenoDX содержит создание feature 18 и успешные inline evaluations без последующей ошибки; вывод на экран действительно получает обработанный ресурс. `NGX Evaluate success` относится к carrier и отдельно этого не доказывает. Проверять изображения и движение, а не только сообщения.

## 5. Контракт рендера и NGX

Первое разрешение: 1280×720, SDR, без апскейлинга, dynamic resolution, HDR и frame generation. Render size = output size. Не повышать разрешение до G1.

| Буфер | Формат и смысл |
|---|---|
| Color / Output | `R16G16B16A16_FLOAT`, линейный RGB; текстуры sRGB декодируются ровно один раз |
| Depth | `R32_TYPELESS` ресурс, `D32_FLOAT` DSV / `R32_FLOAT` SRV; обычный device depth [0,1], near=0, far=1 |
| Motion | `R16G16_FLOAT`; previous minus current в пикселях render resolution; X вправо, Y вниз |
| Swapchain | `R8G8B8A8_UNORM`, единственное linear→sRGB преобразование при финальном выводе |

Сцена записывает все три буфера с одинаковой геометрией, alpha test и покрытием. Прозрачный texel не пишет ни depth, ни motion. Фон: depth=1, motion=0. Первый этап использует непрозрачные и alpha-tested поверхности; полупрозрачные декоративные эффекты можно исключить только явно в отчёте покрытия.

Создать DLAA через `NGX_D3D12_CREATE_DLSS_EXT`, качество `NVSDK_NGX_PerfQuality_Value_DLAA`, размеры входа и выхода одинаковы. Flags: `MVLowRes | IsHDR | AutoExposure`; HDR flag здесь описывает линейный float-вход NGX, а не HDR-монитор. Не задавать `DepthInverted` или `MVJittered`. Использовать `NVSDK_NGX_D3D12_Init_with_ProjectID` с постоянным UUID **`d91e6822-7691-4ad8-a81b-597ed04e49ef`**, custom engine. Это ID данного прототипа, не чужой application ID.

Evaluate: `NGX_D3D12_EVALUATE_DLSS_EXT`; `Feature.pInColor`, `Feature.pInOutput`, `pInDepth`, `pInMotionVectors`; `InMVScaleX=InMVScaleY=1`; `InRenderSubrectDimensions={W,H}`; `InPreExposure=InExposureScale=1`. Для первой версии **jitter=0**, это ограничение качества carrier, не полноценный temporal AA. Не добавлять jitter в одной матрице без соответствующей правки motion и NGX.

Формула движения для одной и той же точки поверхности:

```hlsl
float2 currUV = float2(currClip.x / currClip.w * 0.5 + 0.5,
                      0.5 - currClip.y / currClip.w * 0.5);
float2 prevUV = float2(prevClip.x / prevClip.w * 0.5 + 0.5,
                      0.5 - prevClip.y / prevClip.w * 0.5);
float2 motionPixels = (prevUV - currUV) * float2(width, height);
```

`prevClip` учитывает предыдущие world/view/projection и предыдущую ориентацию billboard; не только предыдущую камеру. Матрицы и порядок умножения задать единообразно в CPU/HLSL. Если прошлое положение непригодно (первый кадр, camera cut, resize, смена проекции), передать `InReset=1`, предыдущие трансформы приравнять текущим. При изменении изображения/направления персонажа без соответствия texel историю также сбросить; не выдавать нулевые векторы за корректное движение.

Перед Evaluate inputs → `NON_PIXEL_SHADER_RESOURCE`, output → `UNORDERED_ACCESS`; далее UAV ordering и переход output к чтению финальным проходом. Дожидаться GPU fence перед повторным использованием allocator, readback или уничтожением ресурсов. После NGX восстановить собственные descriptor heaps и состояние следующего прохода. Resize: drain queue → пересоздать ресурсы/feature → reset. При ошибке остановить neural-run с ненулевым кодом; интерактивный режим может предложить запуск native, но не скрытый fallback с надписью DLSS5 ON.

## 6. Карта и геометрия

Экспортировать только `kladwtwn`, стандартную elevation, без overlay. Точная команда есть в плане. Экспортёр читает master.dat → critter.dat → patch000.dat, а извлечение пишет в собственный `game/data`. Требуется английский набор; он найден в Steam-конфигурации, успешность чтения архивов ещё проверит исполнитель.

На закреплённом commit `scene.json` имеет **`format: 6`**. Проверять формат строго. Основные поля: `proj`, `spawn`, `tiles`, `floor`, `roof`, `pages`, `sprites`, `walls`, `trims`, `doors`, `boards`, `props`, `forms`, `decals`, `sets`, `critters`, `light`. `floor`/`roof` — base64, 100×100 little-endian uint16, 0 означает пустоту, прочее индекс ячейки +1. Это не готовый glTF и не массив треугольников.

Канонические преобразования: `viewer/geom.js` (`Proj`, `card`, `hexPx`, `rowPlane`) и `viewer/render.js` (`Renderer`, создание batches, `sheet`, `board`, `solid`, `form`). Брать численные коэффициенты из `scene.proj`. UV учитывают atlas margins, размеры страницы и sprite anchor `ox/oy`; запретить выход индексов за диапазон, несоответствие длины распакованного пола и отсутствующие изображения.

В прототипе обе камеры смотрят на **одну геометрическую сцену**, собранную по правилам first-person ветки upstream. Для props/forms соблюдать `hidden`, `hiddenWalls`, `hiddenRoof`, чтобы не рисовать заменённые карты дважды; учитывать `lifts`, `rests`, `crossed` и shadow separation. В изометрии не переносить painter-order depth overrides оригинальной игры в neural depth. Визуальное отличие от оригинального изометрического режима из-за этого допустимо и отмечается в отчёте. Перспективный upstream-вид — основной референс геометрии.

После экспорта создать `reports/scene-coverage.json`: для каждого визуального поля число входных/отрисованных/исключённых объектов и причина исключения. Нельзя молча пропустить непустые props/forms/critters или заменить всю карту скриншотом. Если выбранная карта содержит неподдержанную геометрию, доделать её до G2. Игровые метаданные и коллизии загружаются только при необходимости; их отсутствие в рендере не ошибка. Зафиксировать освещение и время, отключить динамические glows/анимацию для сравнения.

## 7. Приёмка и остановка

| Gate | Доказательства |
|---|---|
| G0 — воспроизводимость | hashes исходных файлов совпали; dependencies/toolchain записаны; сборка x64; лицензии сохранены; native запускается без нейробиблиотек |
| G1 — feasibility, до экспорта карты | синтетическая сцена с текстурным полом, коробками, alpha-card и движущейся камерой; native/carrier/neural; 300 последовательных успешных carrier Evaluate; свежие feature-18 create/evaluate; PNG до/после и короткий захват движения; оба типа проекции |
| G2 — карта | экспорт одной карты; полный coverage; узнаваемая сцена, правильные масштабы/UV/перекрытия; две камеры; debug depth/MV и численные проверки |
| G3 — итог | отдельные фиксированные прогоны трёх режимов, метрики и изображения; повторный старт, resize, camera cut без повреждения вывода; source hashes не изменились |

Численные проверки: неподвижные геометрия/камера дают motion ≈0; тестовая точка с currentUV=(0.6,0.5), previousUV=(0.5,0.5) при 1280×720 даёт (-128,0); near/far depth не перепутаны; alpha holes не закрывают задний объект. Допуск вычисления motion на CPU 1e-4; для readback RG16F — 0.25 пикселя в тестовом диапазоне. Проверять readback внутренних буферов, а не их цветную визуализацию.

Каждый benchmark: новый процесс, уникальная папка `runs/<UTC>-<mode>/`, 15 секунд прогрева, 60 секунд замера. Одинаковые размер, камера/маршрут, свет, режим present и комплект DLL. Фиксированный маршрут задаётся временем, а не числом отрисованных кадров; PNG для сравнения снимать на одинаковых именованных позах. Во время прогона не переключать режимы, разрешение, параметры или оверлей. Сохранить CPU frame time, GPU scene/NGX/total timestamps с frequency, median и p95; FPS считать по длительности измеренной серии, не средним мгновенных FPS. GPU NGX — время блока carrier плюс перехватчик, не обещание отдельного внутреннего NR timing.

Успех интеграции и полезность изображения оценивать отдельно. Ориентир для практической приёмки: neural >=30 FPS при 1280×720, p95 frame time <=50 ms, видимое улучшение деталей/света без разрушения силуэтов и устойчивых шлейфов. Это проектная цель, не прогноз RTX 5070. Если пользователь не оценил изображение, написать «технически работает, визуальная приёмка ожидается».

При отсутствии feature-18 evidence, crash/device removal или невидимом результате G1 — максимум **два исправления с конкретной причиной**, суммарно до двух часов диагностики после первой готовой сборки теста. Затем сохранить failure report и остановиться; не переписывать рендерер, не качать цепочку случайных версий. Провал runtime при корректных inputs может быть внешним ограничением. При недостаточном FPS в G3 сначала локализовать стоимость по трём режимам; результат ниже порога не объявлять архитектурной невозможностью.
