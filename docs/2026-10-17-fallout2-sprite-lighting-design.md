# Fallout 2: CE с объёмным окружением и оригинальными спрайтами

Дата: 2026-10-17. Редакция 2. Актуальная спецификация для агента-исполнителя.

**Решение пользователя:** сохранить игру и её механики в CE, использовать реконструкцию окружения по принципам Apolotary/fallout2-first-person. Сначала живой участок Кламата; остальные карты — после подтверждения интеграции.

Эта редакция заменяет прежнее направление «перспективные картонки + свет» в этом файле. Прежний план перспективных картонок и документы native-dlss5 от 2026-10-12 исторические. Текущий технический план P0–P1: `2026-10-17-fallout2-ce-3d-env-p0-p1.md` в этой папке.

## 1. Цель и границы

Та же Fallout 2: пошаговый бой, квесты, диалоги, инвентарь, сохранения, атмосфера. Изображение — исходные текстуры и спрайты, объёмное окружение, фиксированная перспективная камера сверху под углом, затем динамический свет.

Приоритет: полноценная игра → правильная геометрия и управление → свет → производительность → остальные карты → установка. DLSS5 остаётся необязательной поздней целью.

- Windows x64. Основа игры (решение пользователя 2026-10-18): оригинальная Fallout 2 из Steam + Restoration Project (RPU) v2.4.34 от BGforge с русским переводом. Исходная установка D:\SteamLibrary\steamapps\common\Fallout 2 — только чтение.
- Рабочий проект E:\Projects\fallout2-ce-3d; запуск на копии в game/.
- Русский язык — перевод из релиза RPU (`rpu_russian.dat`, `upu_russian_sound.dat`). Репак E:\Games\Fallout 2 основой не является; из него позже берётся только оформление нижней панели.
- Персонажи остаются спрайтами. Простая геометрия стен, мебели, крыш и ориентиров входит в задачу.
- Полные новые модели персонажей, шутер, свободное вращение камеры, изменение правил и нейросетевая перерисовка не входят.
- Не строить сначала просмотрщик всех карт, чтобы потом заново писать в нём игру.

## 3. Архитектура

```text
INPUT: ресурсы установленной игры + живое состояние CE + настройки камеры.
TRANSFORM: локальный конвертер восстанавливает поверхности, текстуры и привязки.
TRANSFORM: адаптер CE передаёт актуальные объекты, двери, крыши и кадры анимаций.
TRANSFORM: GPU рисует геометрию и спрайты одной камерой, затем исходный UI.
MEANING: реконструкция меняет изображение; правила и состояние остаются в CE.
OUTPUT: играбельная Fallout 2 с объёмным окружением и перспективой.
DIRECT CHECK: один сейв и одинаковые действия в штатном и новом рендерах.
```

### CE — единственный владелец игры

Не переписывать бой, скрипты, ИИ, путь, инвентарь, сохранения и игровой свет. Рендер читает состояние; выбор мышью преобразуется в обычные действия CE. Геометрия не создаёт независимый мир коллизий: проходимость и взаимодействия определяет движок.

### Конвертер — представление окружения

Адаптировать существующий Python-конвертер, не писать заново DAT/MAP/FRM-парсеры без установленной необходимости. Изучить tools/fp/scene.py, proj.py, модули стен/предметов, viewer/geom.js и render.js.

| Содержимое | Представление |
|---|---|
| Пол, крыши | Поверхности с текстурами, преобразованными из исходной изометрии |
| Распознанные стены | Плоскости нужного направления, толщина, верхняя грань |
| Двери | Отдельные элементы, управляемые состоянием и анимацией CE |
| Мебель и декорации | Простые формы из правил донора: коробки, цилиндры и прочее |
| Персонажи | Исходный направленный спрайт и актуальный кадр CE |
| Неизвестные объекты | Видимый fallback: корректно привязанный спрайт/наклонная плоскость |
| Плоские объекты | Декаль, если классификация подтверждена |

Сохранять гекс, elevation, опорные точки и FRM offsets. Высота картинки не равна высоте объекта: низ может изображать глубину/землю. Запрещён универсальный подход C1 «все объекты вертикальные, высота = frameHeight».

Скрытые стороны — приближение, не восстановленная истина. Не удалять неизвестные объекты ради красивого кадра. Для каждой карты считать геометрические объекты, fallback и ошибки; исключения должны быть видны в отчёте.

### Живые объекты и кэш

Статический экспорт не является сейвом. Двери, персонажи, предметы, контейнеры и меняемые скриптами элементы обновляются из CE. После открытия/удаления нельзя оставлять запечённую копию.

Минимальный контракт адаптера (проектные данные, не утверждение о готовом API):

| Данные | Требование |
|---|---|
| Карта | Идентификатор, elevation, generation загрузки, преобразование координат |
| Объект | Runtime handle с generation; привязка к исходному MAP-объекту, если существует |
| Положение | Гекс, elevation, смещение движения/анимации, опорная точка |
| Вид | PID/FID или эквивалент, направление, кадр, FRM offsets, палитра/alpha, видимость |
| Изменения | Создание/удаление, движение, смена вида, дверь, скрытие крыши |
| Выбор | Соответствие видимой поверхности/спрайта объекту CE |

Одинаковые PID не означают один объект. Адрес памяти не является постоянным ключом. После load/смены карты пересоздавать runtime-привязки. Брошенные и созданные скриптом объекты работают без заранее существующей записи в экспорте.

На маленьком участке допустима синхронизация списка на каждом кадре. Снимать состояние в согласованной фазе игрового цикла; не читать изменяемые указатели асинхронно.

Кэш содержит версию формата/конвертера, отпечатки входных ресурсов и параметры. При изменении данных пересобирается. Повреждение даёт диагностику и возврат к штатному виду. Соблюдать фактический порядок ресурсов CE, включая loose-файлы: донорский экспорт трёх DAT не гарантирует соответствия локализованной установке.

### Нативный рендер

Одно приложение и одно игровое окно CE. Браузер донора — визуальный эталон, не второй игровой движок.

Предпочтительный backend первого прототипа: OpenGL 3.3 через SDL2, с явной адаптацией алгоритмов/шейдеров WebGL2. Сначала проверить GPU-контекст, исходный UI, resize и возврат к штатному выводу. Это ещё не проверенная интеграция. Если такой путь конфликтует с CE, описать конкретную причину и обновить технический план до переноса сцены.

Нужны depth buffer, alpha-маски, согласованное перекрытие поверхностей и спрайтов. Сохранить палитру, cycling, fades, прозрачность и выделение. Однократное преобразование в RGB не должно замораживать палитровую анимацию.

UI, меню, текст, диалоги и видео не подвергать перспективе/освещению. Штатный рендер сохраняется как контроль и fallback. Для технического выбора backend сначала допустим перезапуск; приёмочное сравнение штатного/нового вида должно переключаться на живой сцене без сброса игры.

## 4. Камера и управление

- Настоящая перспектива сверху под углом, фиксированное направление, pan, ограниченный zoom. Ракурс согласован с нарисованными сторонами спрайтов.
- Показать два варианта силы перспективы на одном сейве с сопоставимым центральным охватом. FOV/pitch/distance/zoom фиксировать.
- Геометрия, объекты, тени и picking используют одну систему координат. Учитывать elevation, viewport, DPI/размер окна. Координаты ванильного экрана не считать готовыми мировыми координатами.
- Земля выбирается лучом на плоскость текущего этажа. Объект — по его видимому представлению и handle; проекции на землю недостаточно для двери/высокой стены.
- Прозрачные пиксели не перехватывают выбор. Курсор/выделение совпадают с изображением в центре и у краёв; UI обрабатывает свои клики первым.
- Сохранить скрытие крыш, видимость за стеной и спецпрозрачность CE. Старый порядок рисования не доказывает корректность новой перспективы.
- Не маскировать потерянные тайлы виньеткой. Отличать настоящий край карты от ошибки отсечения; ограничивать pan доступной сценой.
- Штатный/новый вид и свет OFF/ON переключаются независимо. Temporal-история сбрасывается при смене вида, если появится.
- Направление и кадр персонажа берутся из CE. Не растягивать спрайт и не ускорять игровую анимацию ради FPS.

## 5. Свет и аутентичность

Первый показ — без нового света. После принятия геометрии добавить один перемещаемый точечный источник: разные стороны стены, пол и предмет реагируют на направление/расстояние. Затем привязать его к существующей лампе/огню.

Геометрия использует свои нормали. Для персонажей/fallback сначала допустим аккуратный упрощённый свет. Normal/height maps — только для проверенного набора; одна карта на все позы персонажа запрещена. Яркость исходной картинки не доказывает форму поверхности.

Учитывать уже нарисованные тени. Сохранить палитру/фактуру; не подменять объём глобальным глянцем/bloom. Новые тени — после принятия света, с проверкой открытой/закрытой двери и крыши.

Новый свет не влияет на скрытность, попадания, видимость и другие правила CE. Свет OFF убирает новый эффект, но не обязан делать реконструированную сцену попиксельно равной оригиналу. Для этого сравнения есть штатный рендер.

## 6. Этапы и приёмка

### P0 — технический план и вывод

Исследовать реальные точки подключения src/svga.cc, tile.cc, object.cc, art.cc, game_mouse.cc, map.cc, palette.cc. Новый план содержит конкретные файлы/функции, контракт состояния, координаты, кэш, зависимости и команды проверок. Не выдавать предполагаемые функции за существующие.

Сохранить C1. Проверить GPU + исходный UI внутри CE, штатный запуск, resize и возврат к старому виду. Примитив допустим для короткой проверки контекста, но не считается визуальным результатом.

### P1 — живой участок Кламата

#### Обязательный dev-режим для исполнителя (добавлено 2026-10-18)

Перед следующими визуальными проверками реализовать инструменты исследования карт внутри игрового CE. В mapper есть образец списка карт (`src/mapper/map_func.cc`, `map_load_dialog`), но запуск редактора не заменяет проверку механик в игре. Текущий `--dev-load-game=N` загружает только сейв; готового CLI выбора карты в проверенном `src/main.cc` нет. Конфиг `[debug] mode=environment` сам по себе такой режим не включает.

- Dev-запуск всегда оконный (`[screen] windowed=1` в рабочей копии), без вступления и ручного создания персонажа. Отдельный launcher использует фиксированный тестовый профиль/копию сейва, по умолчанию Кламат `kladwtwn`, elevation 0. Обычный запуск сохраняет своё назначение.
- Добавить явный `--dev-tools` и в этом режиме `--dev-map=kladwtwn`, `--dev-elevation=0`, `--dev-list-maps`. Это требуемые новые опции, не уже существующие команды. Список строить из доступных игровых ресурсов, а не из 12 featured-карт донора; доступные этажи проверять по данным карты.
- В самой игре: компактная панель с поиском/выбором карты, выбором доступного elevation и кнопками предыдущая/следующая карта. Предусмотреть клавиатурный доступ без конфликта с обычными действиями. Текущие карта/elevation и активный рендер видны в панели.
- Загрузку выполнять штатным переходом CE в безопасной фазе цикла. Не копировать вызов `mapLoadByName` из mapper в произвольный обработчик: завершить старое состояние, пересоздать привязки рендера, восстановить курсор/UI. Во время боя, диалога, видео или загрузки переход отклоняется с понятным сообщением либо откладывается до безопасного состояния.
- После переключения герой стоит на допустимой входной клетке соответствующего этажа, камера центрируется. Ошибка имени/этажа не оставляет полузагруженную сцену. Сохраняются обычные скрипты карты: dev-телепорт не отключает их ради красивой картинки.
- Переключатели штатный/новый рендер и свет OFF/ON независимы. Если новый рендер карты не готов, панель явно сообщает fallback; нельзя выдавать штатную картинку за результат реконструкции.
- Кнопка/хоткей снимка сохраняет изображение и метаданные: карта/elevation, камера, рендер, свет, внутреннее разрешение, commit CE/инструментов и SHA-256 EXE. Метаданные брать из фактического состояния, а не из запрошенных параметров запуска.
- Dev-сессия использует отдельные тестовые сохранения/изменяемые данные карты; не перезаписывает пользовательские слоты и ресурсы исходной игры. Перемещение между картами отладкой не является доказательством штатных квестовых переходов или проходимости кампании.

Приёмка dev-инструментов: одним запуском открыть Кламат, перейти на другую доступную карту, выбрать существующий этаж, вернуться в Кламат; проверить героя/камеру/picking, отсутствие старых объектов, отказ на несуществующем имени/этаже, сохранить снимок с метаданными. Записать точную команду launcher и краткую инструкцию для следующего агента. Не объявлять панель готовой по факту включения debug-логов или оконного режима.

Карта kladwtwn, elevation 0. Экспортировать достаточно окружения для участка и движения камеры. Выбрать участок со стеной, дверью, предметом/контейнером и NPC. До приёмки записать конкретные объекты, сейв, камеру и последовательность действий. Не заменять Кламат храмом или синтетической сценой без обоснования.

| Проверка | Условие PASS |
|---|---|
| Вид | Пространственные стены, персонажи на земле без сплющивания, нет двойных/пропавших объектов; показаны два варианта камеры |
| Ходьба | Клики в центре и по краям соответствуют гексам; путь/препятствия определяет CE |
| Дверь | Открытие/закрытие согласованно меняет изображение и проходимость; старой копии нет |
| Предмет | Поднять, бросить, снова выбрать; изображение соответствует инвентарю |
| Разговор | Настоящий диалог с NPC из нового вида, исправный UI |
| Бой | Выбор цели, движение, атака, завершение хода и ход противника; AP/анимации из CE |
| Save/load | Сохранить изменённые дверь/предметы, перезапустить и загрузить; всё восстановлено |
| Переход | Уйти на другую карту и вернуться без старых объектов/handle; неподдерживаемая карта явно использует штатный рендер |
| Режимы | Переключение вида без сброса игры; выделение, крыши и UI работают |

Свидетельства: короткая непрерывная запись действий, парные кадры одного состояния, журнал ошибок, оба commit, SHA-256 запущенного EXE. Скриншот или экспорт не заменяет игровые проверки.

**До массовой конвертации пользователь должен принять внешний вид P1.** Если картинка не подходит, исправить её на одном участке.

### P2 — свет и производительность

Показать light OFF/ON при одной камере, перемещение источника вокруг стены/предмета. Поверхности реагируют; UI и правила неизменны. Проверить анимации, прозрачность и конфликт с нарисованными тенями.

Цель: 60 FPS при 1920×1080 на RTX 5070 пользователя. Записать CPU/GPU/драйвер, настройки и внутреннее разрешение. Одинаковый маршрут: 15 секунд прогрева + 60 секунд измерения отдельно для штатного вида, нового без света и нового со светом. Сохранить median/p95 CPU/GPU frametimes и интервала кадра. Критерий: median и p95 интервала кадра ≤16,7 мс без скрытого снижения разрешения; загрузки измерять отдельно. Отсутствующие GPU-метрики отметить, не делать по одному FPS вывод о стоимости света.

Игровое время и темп анимации не ускоряются. 60 FPS вывода не означают 60 уникальных исходных кадров персонажа.

### P3 — все карты

После P1/P2 конвертировать оставшиеся карты. Перечень строить из ресурсов/реестра игры, включая используемые elevations, интерьеры и случайные встречи; 12 featured-карт недостаточно.

Машинный отчёт: карта/elevation → экспорт → загрузка CE → геометрия/fallback → визуальная проверка → игровая проверка → ошибки. Не смешивать успешный экспорт с подтверждённой играбельностью. Повторный запуск использует только валидный кэш с совпадающими входами.

Для заявления «все карты переведены» — полный перечень, отсутствие исключений штатного рендера и визуальная проверка каждой пары карта/elevation. «Игра проходима» требует отдельных проверок маршрутов/квестов. Матрица поведения включает улицу, тесный интерьер, пещеру, лифт/этажи, случайную встречу, крыши, прозрачные стены и скриптовое создание/удаление.

### P4 — русский язык и установка

Русификатор выбран: перевод RPU v2.4.34 (источник и хеши — в `docs/game-setup.md`). Ресурсы на месте, внешний вид в игре ещё не проверен. Проверить меню, диалоги, журнал, переносы, шрифты, озвучку при наличии. EXE-патчи и изменение логики не обещать поддерживать как обычные ресурсы.

Установка использует имеющуюся игру и создаёт изолированный каталог мода/кэша. Не перезаписывает исходные EXE, DAT, конфиги, сейвы. Проверить установку, обновление, отключение и запуск оригинала. Сейвы CE отделить; совместимость с оригинальным EXE испытывать только на копиях.

### P5 — необязательный DLSS5

Отдельное исследование после принятой полезной игры. Выбор OpenGL не гарантирует будущую совместимость NVIDIA runtime. Базовый мод без neural DLL; экспериментальный комплект из старого проекта не включать в релиз автоматически.

## 7. Структура, проверка и воспроизводимость

Сохранить ce/, build/, game/, tools/, docs/, runs/. Предлагаемые области: ce/src/scene_renderer/ — GPU и адаптер; tools/scene_export/ — конвертер; game/mod-cache/ — производные данные. Эти новые пути ещё не заявлены реализованными; уточнить в техническом плане.

Следовать стилю CE/донора, не форматировать весь upstream. Разделить координаты, адаптер и вывод. Значимые автоматические проверки: преобразование/обратная проекция на разных elevations, одинаковые PID, создание/удаление, reset/load, инвалидация кэша. Формальный тест формулы не заменяет визуальную и игровую приёмку.

Существующие команды PowerShell:

```powershell
git -C 'E:\Projects\fallout2-ce-3d' status --short
git -C 'E:\Projects\fallout2-ce-3d' rev-parse HEAD
powershell -NoProfile -ExecutionPolicy Bypass -File 'E:\Projects\fallout2-ce-3d\tools\configure-build.ps1' Release
Get-FileHash -Algorithm SHA256 'E:\Projects\fallout2-ce-3d\game\fallout2-ce.exe'
Start-Process -FilePath 'E:\Projects\fallout2-ce-3d\game\fallout2-ce.exe' -WorkingDirectory 'E:\Projects\fallout2-ce-3d\game'
```

Скрипт сборки может пересоздавать build при смене генератора: сначала прочитать, сохранить нужные артефакты. Сборка не доказывает обновление game/EXE: проверить путь результата/копирования и хеши, записать команду установки сборки. Новые команды тестов/экспорта добавить после создания инструментов, не выдумывать готовые команды.

## 8. Распространение и сохранность

Бесплатный некоммерческий мод с доступными исходниками. Сохранить LICENSE/NOTICE обоих upstream, отметить заимствования/модификации, не перелицензировать чужой код в MIT/GPL. Перед выпуском проверить условия закреплённых зависимостей.

DAT, извлечённые арты, музыка, ролики, сейвы, русификатор и производные сцены не включаются в Git/публичный пакет. Конвертация локальная из установки пользователя. Публикуются разрешённый код и инструменты, с указанием неофициального статуса; это не гарантия отсутствия претензий.

Не трогать dirty-конфиги старой установки и чужую работу. Локальные коммиты небольшие, исходники CE сохранены отдельно от внешних документов. С 2026-10-18 пользователь поручил вести GitHub: принятые этапы коммитятся и публикуются в закрытых репозиториях проекта; релизы остаются отдельной задачей.
